# 虎航票價追蹤

台灣虎航 2027 年 1–3 月來回票價追蹤，跑在 **GitHub Actions** 上，每 15 分鐘自動抓一次。
不需要任何本機環境、不需要瀏覽器、不需要你的電腦開著。

**公開頁面：** https://yenzackary.github.io/tigerair_fare_tracker/

**追蹤條件**：2027-01-01 ~ 2027-03-31 出發、行程 3–5 天（含頭尾）、且區間內同時涵蓋週六與週日、
1 位成人、不含託運行李。桃園／台中／高雄／台南出發的所有航點，目前 44 條來回航線、88 個航段。

**金額一律是實付總額** ＝ 未稅票價 ＋ 去程稅費 ＋ 回程稅費。

## 怎麼運作

```
GitHub Actions（每 15 分鐘）
  └─ node tools/watch.mjs
       ├─ 抓虎航每日票價 API（4 個台灣機場）
       ├─ 算出每條來回航線在條件內的最低價
       ├─ 跟 tools/state.json 比對 → 判斷「新低價」與「一般變動」
       ├─ 有事就在「虎航票價通知」Issue 留言 → GitHub 寄信給你
       └─ 重新產生 index.html / all-routes.html / status.html
  └─ 有變動就 commit 回 repo → GitHub Pages 自動更新
```

票價 API 的 CORS 鎖在 `tigerairtw.com` 網域，但**CORS 只有瀏覽器會執行** ——
Actions runner 上的 Node 不送 `Origin` header，所以可以直接呼叫。

## 通知

通知貼在 repo 的 **「虎航票價通知」Issue** 裡。你是 repo 擁有者，GitHub 會把每一則留言寄到你的信箱，
所以那個 Issue 就是通知信的來源。**不要關閉它** —— 關掉之後程式會另外開一個新的。

| 事件 | 條件 | 節流 |
|---|---|---|
| **新低價** | 某航線未稅來回合計跌破**歷史最低** | **不節流，一定發** |
| **每日摘要** | 台北時間 08:00 之後第一次執行 | 每天一次 |
| **一般變動** | 最低價跟上次比有動，但沒破歷史最低 | 每 60 分鐘最多一則 |

幾個刻意的設計：

- **新低價絕不漏發**：不受節流限制，也不受「今天摘要已發」影響。同一條航線 24 小時內用同一個價位
  不會重複發，價位不同就會再發。
- **通知失敗不會阻擋資料更新**，而且失敗時不寫入「已通知」記錄 —— 下一次執行會自動重試。
- **新低價發出時就不再發一般變動**，避免同一件事洗兩則；那些變動仍會出現在當天的摘要裡。
- **第一次執行只建立基準**，不發新低價或變動通知（沒有歷史可以比）。
- 「新低」用的是**歷史最低**，不是「跟上次比」—— 後者只是一般變動。

想調整就改 `tools/watch.mjs` 最上面那段常數：`CHANGE_THROTTLE_MIN`、`DAILY_SUMMARY_HOUR`、
`MAX_*`（訊息最多列幾條）。追蹤條件也在同一區：`DATE_FROM`、`DATE_TO`、`TRIP_NIGHTS`、`REQUIRE_WEEKEND`。

## 頁面

| 檔案 | 內容 |
|---|---|
| `index.html` | 首頁：最便宜的 5 條 + 入口 |
| `all-routes.html` | 全航線儀表板：排行、長條圖、價格日曆、單程走勢、所有組合、稅費查核進度 |
| `status.html` | 變動與通知紀錄（只記有意義的事件 + 每小時一筆例行檢查） |

**想看每一次執行的完整紀錄與 log，去 [Actions 頁](../../actions)** —— 那才是完整的執行歷史。
`status.html` 只記錄有意義的事件，避免每 15 分鐘產生一個 commit。

## 手動觸發與試跑

到 [Actions 頁](../../actions) → 選「虎航票價追蹤」→ Run workflow。
勾 **dry** 就是試跑：照樣抓價、把本次會發的通知內容印在 log 裡，但**不發通知、不改任何檔案**。
第一次設定完或改過條件之後，建議先用 dry 跑一次看輸出對不對。

本機也可以跑（需要 Node 18+，無外部套件）：

```bash
node tools/watch.mjs --dry                     # 抓真的 API，但不通知不寫檔
node tools/watch.mjs --fixture=<快照.json>     # 完全離線
node tools/watch.mjs --summary                 # 強制發每日摘要
```

## 稅費那張表（重要）

`tools/data.mjs` 的 `LEG_TAX` 是 **88 個航段一段一段從虎航官網訂票引擎購物車實測**得到的，
並以「總計金額 = 兩段票價 ＋ 兩段稅費」對帳驗證過。**不是推估值，也不要用規律去猜** ——
實測證明同一個國家不同機場差很多：

| 航段 | 稅費 | 對照 |
|---|---|---|
| 桃園 → 沖繩 | 800 | 桃園 → 石垣島 900（同為日本）|
| 沖繩 → 桃園 | 1,145 | 沖繩 → 高雄 1,245（同起點，終點不同就不同）|
| 大阪 → 桃園 | 1,624 | 石垣島 → 桃園 899（同為日本出發）|
| 釜山 → 桃園 | 725 | 仁川 → 桃園 837、濟州 → 桃園 825（同為韓國出發）|

用國家去推的誤差最大到 **799 元**，所以這張表只能實測。

**⚠ 2026-09-01 台灣機場服務費由 500 調升為 750**（2028-09-01 再升至 1,000）。
屆時所有「台灣出發」航段（`TPE-` / `RMQ-` / `KHH-` / `TNN-` 開頭，共 44 個）都必須**重新實測**，
不能用舊值 +250 —— 虎航按開票日還是旅行日認定尚未確認。

若某航段在 `LEG_TAX` 裡找不到（例如虎航開了新航點），程式會把該航線標成「稅費未實測」
並改用未稅價顯示，**不會拿估的數字冒充含稅價**。

## 設定（只需做一次）

1. **Settings → Actions → General → Workflow permissions** 選 **Read and write permissions**。
   workflow 需要這個權限才能把更新後的頁面 commit 回來、以及在 Issue 留言。
   （`.github/workflows/watch.yml` 裡已經把權限收窄成只有 `contents: write` 和 `issues: write`。）
2. 到 Actions 頁手動跑一次（建議先勾 dry 看輸出）。
3. 確認 **Settings → Pages** 的來源是 `main` 分支根目錄。

不需要任何 secret、不需要 token。

## 限制

- Actions 的 cron 最短 5 分鐘，而且公開 repo 在 GitHub 負載高時可能延遲幾分鐘，不保證準時。
- 排程在 repo 連續 60 天沒有 commit 時會被 GitHub 自動停用。本 workflow 本身會 commit，
  正常運作下不會觸發，但如果長期沒有任何票價變動，記得偶爾手動跑一次。
- 票價隨機位變動，實測一小時內就會變。本頁僅供參考，非台灣虎航官方頁面，下訂請以官網結帳頁為準。
